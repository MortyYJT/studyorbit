# 第 0 层：课程列表验证脚本

这是独立实验，不调用 Agent，不安装扩展，不修改前端或旧项目。
当前仅实现 macOS；Windows 操作适配待做。

## 运行

先在常用浏览器登录墨大 LMS，再在项目目录运行：

```sh
npm run sync:courses
```

默认使用系统默认浏览器。也可指定已登录的浏览器：

```sh
npm run sync:courses -- --browser edge
npm run sync:courses -- --browser chrome
```

还接受 `safari`、`firefox`、`brave` 参数，但这些浏览器尚未经真实页面验证。
如果有多个浏览器配置，普通打开链接行为可能选中未登录的配置，需要用户确认。

脚本立即打开一次 API 页面，默认等待 1 秒，只全选复制一次，随后立即解析并返回；不循环复制、不刷新、不翻页、不自动重试。运行期间保持浏览器前台，不操作键盘。
首次运行可能需要给启动脚本的终端（或承载终端的应用）授予：

- 系统设置 → 隐私与安全性 → 辅助功能。
- 系统设置 → 隐私与安全性 → 自动化 → 允许控制 System Events。

如果跳到登录页面，先完成登录，再重新运行。页面慢时可用 `--wait 3`，只增加复制前的等待时间，不增加读取次数。
`Control + C` 可停止；复制过程使用剪贴板，结束时尽量恢复原有纯文本，但不保留图片或富文本。

## 结果与范围

脚本在浏览器打开以下接口，通过全选、复制读取文本并由本地 Node.js 解析：

```text
https://canvas.lms.unimelb.edu.au/api/v1/courses?enrollment_state=active&include[]=term&per_page=100
```

此版与旧扩展保持相同范围：只读取 API 第一页，不额外打开第二页。
输出用 `scope: "first_page"` 和 `paginationVerified: false` 标记范围，不声称已验证全量。
达到 100 条时终端提示可能还有下一页；即使不足 100 条，也没有验证服务器分页上限。
旧版本在第一页成功读到 9 条后，第二页失焦或复制超时，导致整次失败；本次删除了该额外步骤。
旧版本读取失败会重复聚焦地址栏并复制，看起来像反复跳转。本版删除了循环，只保留一次读取；失败直接显示原因，已有输出不变。
读取的是 active enrollment 的 API 候选列表，不保证等同于首页卡片，也不代表账号的所有历史课程。
原始数据保留所有条目；返回前端前按课程代码筛选。当前规则要求 `course_code` 以四个英文字母、
一个 1–9 的数字和四个数字开头，后面接下划线或结尾。它能筛出当前四门课程，并排除 `MPMP00101`。
这是根据当前样本制定的规则，并非经过全校课程验证的完整分类；不符合规则的课程不会显示在选课列表中。

结果显示在终端，并写入 `.local/lms/courses.json`，包含课程 ID、名称、代码、学期、链接、获取时间和耗时。
输出通过临时文件替换，失败不会覆盖旧结果；`.local/` 已排除在 Git 外。
可用 `--out 路径` 指定其他输出位置，自定义位置不一定被 Git 忽略。

运行 `npm run dev` 后打开本周页面，点击“立即同步”会运行此脚本，随后选课列表读取筛选结果；选择保存在当前浏览器的 localStorage。
脚本使用系统默认浏览器，并会打开 API 标签页；读取结束后需返回前端页面。启动开发服务器的终端需要对应系统权限。
这个前端连接目前只由 Vite 开发服务器提供，未接入正式后端或后续排期。

这次需要实际验证：能否打开正确配置、复制到第一页 JSON、实际耗时，以及第二次运行是否正常。
解析逻辑和命令入口已检查；用户已验证旧版本在 Edge 能读到第一页 9 条；本次修改后的浏览器流程仍需用户复测。
