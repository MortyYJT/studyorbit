## 1. 问题和目标

**用户：** 我自己，墨大学生，同时在找实习。只供自用，数据只留在本机。

**现在的问题：**
- 课程信息分散在 Canvas、Ed 和学生邮件里，每门课放的位置不一样（#119）。
- 作业、权重、截止时间要手动抄进 Excel。
- 截止时间改了要靠自己发现。
- 每天做什么靠脑子排，分数要自己算。
- 考前复习材料要自己找、自己整理。

**目标：** 只打开一个前端，就能看到所有课程的情况、本周计划，并通过前端让 agent 帮忙复习和完成作业（#116）。

**成功标准：** 下学期不再手动维护那张 Excel。
**辅助指标（#133）：** 同步耗时和成功率；agent 补全准确率（我先标注一小批评估集）；预计与实际用时偏差（我在前端记录实际用时）；agent 完成作业的步数和费用。

## 2. 架构总览（产品视角）

```
信息源：Canvas(LMS) · Ed · 学生邮件(以后)
          │  常驻浏览器（保持登录）
          ▼
固定代码：同步 → 脱敏 → 本地库 → 排期 · 护栏（授权检查、审计）
          ▲                 │
   agent 批注（带出处）       ▼
agent：读懂课程页、对照要求、操作网页   ←→   前端（唯一入口：查看 + 和 agent 对话）
```

- 每次都一样的事交给代码（读接口、存储、排期、显示、护栏）；每次都不一样的事交给 agent（读懂大纲、找考试范围、操作网页）（#100）。
- 邮件只当提醒，平台数据才算准（#118）。

## 3. 用户故事和验收标准

每条故事的验收标准，就是最后用户验收时逐条打勾的清单。

### US-1 同步和查看课程

作为学生，我想打开前端就看到本学期每门课的作业、截止时间、权重和已出的分数，不用自己去各个平台找。

验收：
- [ ] 一条命令或前端一个按钮同步本学期所有课的 Canvas 和 Ed 数据。
- [ ] 同一门课在 Canvas 和 Ed 上合并成一门（按课程代码，#104）。
- [ ] 前端列出每门课的考核项：名称、截止时间、权重、分数、状态。
- [ ] 平台没给权重的考核项显示「未知」，不猜（#103）。
- [ ] 登录过期时前端明确提示，不显示过时数据却不说明。
- [ ] 同步手动触发；收到相关课程邮件时自动同步（#128，随邮件入口做）。

### US-2 agent 补全平台没有的信息

作为学生，我想让 agent 读大纲和 Ed 上的课程安排，补上权重、哪些是考试 / hurdle、只写在大纲里的考核项，并且每条都能看到出处。

验收：
- [ ] agent 写的每条信息都带原文引文，前端能点开看出处。
- [ ] 引文核对不通过的信息不会写进去。
- [ ] 我手动改的值优先于 agent，agent 优先于平台原值（#103）。
- [ ] 一个考核项可以对应多个平台条目（如 Workshops 10% 对应 10 个 lesson，#105）。

### US-3 每周计划

作为学生，我想设定每天可用的时间，系统按截止时间先后排出本周计划，排不下的提前标出来。

验收：
- [ ] 能设置每天可用时间。
- [ ] 计划按截止时间先后排（结果每次一样，不靠模型）。
- [ ] 排不下的任务单独列出，不悄悄丢掉。
- [ ] 每个任务的预计用时由 agent 估并写理由，我可以在前端改，我的值优先（#131）。
- [ ] 能在前端手动添加校外任务（名称、截止、预计用时），和作业一起排（#132）。
- [ ] 能记录每项任务实际花了多久（用于 #133 的用时偏差）。
- [ ] 排期只排到天（#145）；我可以给任务定开始时间，未定时间的排在当天已定时间的后面；全天任务和截止项单独一行（#143）。
- [ ] 首页是七列周视图（周一到周日），顶部是「需要你处理」，可切到月历（#135、#143）。

### US-4 截止时间变更提醒（以后，#99）

作为学生，收到「截止时间有变」的邮件时，我想系统自动去平台核对，告诉我哪门课哪一项变了。

验收：
- [ ] 收到更改类邮件后，对相关课程重新同步（#118）。
- [ ] 前端提示该课有更新。
- [ ] 只显示最新值，旁边附那封邮件原文；不保留旧值（#130）。
- **【待定，做的时候再定】** 邮件怎么接入学校 Outlook：先核实学校是否允许学生授权第三方应用读邮箱。

### US-5 在前端和 agent 对话

作为学生，我只用这个前端，不想另开第三方 agent 窗口（#116）。

验收：
- [ ] 前端有独立的 Agent 对话页：左边对话历史，右边对话，回复流式显示（#144）。
- [ ] 从考核项、复习、「需要你处理」点进去，会跳到对话页并自动发出预设提示词，带上课程和考核项（#144）。
- [ ] 第一版接 Claude Agent SDK；接入层按多种 agent 设计，以后能加 Codex 等。
- [ ] agent 在浏览器里的写操作（点击、填写、提交）在前端可见，需要确认的在前端确认。
- [ ] MCP 接口保留，外部 agent 仍能用。
- [ ] 我们的代码不直接调模型 API、不存 API 密钥，只启动已登录的 agent（#123）。

### US-6 考前复习

作为学生，我想让 agent 在考前找到考试范围、整理复习笔记和练习题，然后在前端带我复习。

验收：
- [ ] agent 找到每门课的考试范围，并附出处。
- [ ] 复习笔记和练习题存在本地，下次打开还在（#108）。
- [ ] 引用的原文由代码按网址抓取，不是 agent 自己给的（#109）。
- [ ] 复习在课程页的「复习」分页：考试时间、考试范围（带出处）、笔记、练习题统计（#142）。
- [ ] 点「让 agent 带我复习 / 只练错题」跳到对话页，自动发出复习提示词（#144）。
- 不赶今年期末（#127）。

### US-7 作业分级代做

作为学生，我想按课程 AI 政策，让 agent 在允许的范围内帮我做作业。

等级（#120，按作业类型分，高等级包含低等级，#117）：

| 等级 | 能做什么 |
| --- | --- |
| L0 只读 | 获取信息、排期、带我复习 |
| L1 | 自动完成 quiz |
| L2 | 自动完成 assignment、论文等 |

验收：
- [ ] 每门课设一个默认等级，单个考核项可以调高或调低（#117）；只能由我在前端设，agent 没有改授权的命令（#122）。
- [ ] 政策禁止 AI 的课锁在 L0（#124）；没记录政策的课不设上限（#125）；考试不单设代码检查（#126）。
- [ ] 自动完成后默认在前端等我确认再提交，可按课关掉（#121）。
- [ ] agent 每次在浏览器里的写操作都记进审计日志（#111）。
- [ ] 前端能看到每门课的等级（课程页）和审计记录（右上角菜单，#142）。
- [ ] 界面上考试不显示等级，也没有「让 agent 做」入口（#146）。

## 3.5 界面

原型：`design/prototype/index.html`（只用假数据）。布局（#142）：顶部「本周 / Agent」两个入口和右上角头像菜单（同步与登录、指标、审计、设置）；首页左边周视图、右边课程栏；课程页有分数圆环（#141）、AI 政策和等级、「考核项 / 复习」两个分页；考核项详情在侧边抽屉里，值旁标来源（#138）。

## 4. 第一版范围

**做：** US-1、US-2、US-3、US-5、US-6、US-7。
**以后做：** US-4 邮件入口（#129，第一版只有手动同步）；Notion 只读集成（#71）；接 Codex 等更多 agent。

## 5. 明确不做

- 不自建 Canvas 令牌（学校禁止）；模型永远看不到、也不输入密码；MFA 由用户自己完成。
- 不做多用户、线上服务；数据只留在本机。
- 不做笔记或知识库编辑。
- 同学的个人信息不交给模型（quiz / workshop 页面例外，#112）。
