# 课程分析评测

用一份人工核对过的「标准答案」给模型整理结果打分：同一份采集数据跑 N 次，看字段对不对、几次结果是否一致、本地校验拦下了多少错误。脚本是 `scripts/eval-course-analysis.mjs`，打分逻辑在 `scripts/lib/eval-score.mjs`（纯函数，测试 `test/eval-score.test.ts`）。

评测只读已采集的数据：不会启动采集器、不会打开 Edge 或 Ed，也不会写桌面课程文件夹。

## 标准答案

- 每门课一个文件：`<标准答案目录>/<课程代码>.json`，例如 `SYNT10001.json`。
- 格式就是 [课程 JSON v1](course-json.md)（`shared/course-data.ts` 的 `CourseDocumentSchema`），即桌面课程 JSON 加上你在页面里做过的修正。不是外层 `{ status, reason, document }`，只放 `document` 本身。
- `course.code` 必须和课程代码一致，否则报错；不符合 v1 也报错。
- 标准答案含成绩，放在 `.local/` 或别的不入库的位置，不要提交。

## 怎么配对

每个标准答案考核最多配一个模型考核：

1. 先按相同 `id` 配对；
2. 剩下的按名称配对：转小写、标点换成空格、合并空白后相同即可（`Weekly Quizzes` 和 `weekly quizzes!` 算同名）。

没配上的标准答案考核算「漏掉」，没配上的模型考核算「多出」。

## 打分字段

每个配上的考核比较 9 个字段：`kind`、`nature`、`parentId`、`weight`、`maxScore`、`score`、`due`、`scoring`、`status`。

- 数字差 ≤ 1e-6 算相同；`null` 只等于 `null`。
- `due` 只比日期部分（字符串前 10 位 `YYYY-MM-DD`），不换算时区。
- `parentId` 先把模型的父项换成它配上的标准答案 ID 再比：模型叫 `501`、标准答案叫 `canvas-group-501`，只要两者配上了，子项的父项就算对。
- `name`、`rule`、`sources`、`materials` 不打分。

## 指标

| 指标 | 定义 |
| --- | --- |
| 字段准确率 | 对的字段数 ÷（标准答案考核数 × 9）。漏掉的考核 9 个字段都算错 |
| 各字段准确率 | 同上，按字段分开算 |
| 召回 | 配上的标准答案考核 ÷ 标准答案考核数 |
| 精确 | 配上的模型考核 ÷ 模型考核数 |
| 单元格一致 | 每个（标准答案考核, 字段）格子在所有有结果的运行里取值都相同的比例；没配上记作 `<missing>` |
| 与首次相同 | 规范化后与第一次有结果的运行完全相同的运行数 ÷ 全部运行数。规范化只保留 ID、规范化名称和 9 个打分字段，按 ID 排序 |
| 触发修复 | 第一次输出没通过校验、又让模型修了一次的运行数 |
| 最终拒绝 | 模型正常返回、但修复后仍没通过校验、不会保存的运行数 |
| 调用失败 | 模型调用或进程出错、抛出异常或被取消而没有结果的运行数；不算「最终拒绝」 |
| 校验问题 | 模型正常返回的尝试里的问题按条计数（调用失败的尝试不计）；去掉 `assessments.N.` 前缀后合并 |

- 准确率、召回、精确只算「有结果」的运行（通过校验且有 document）。被拒绝、调用失败或模型返回 `failed` 的运行不计入准确率，分别计入「最终拒绝」「调用失败」。
- 多门课的合计用各门课的计数相加后再除，不是平均百分比。
- 每次运行还记录耗时和 token（模型返回了用量时）。

## 运行

```bash
# 合成课程，固定输出，不需要墨大账号和模型密钥
node scripts/eval-course-analysis.mjs --fixture test/fixtures/synthetic-course

# 真实采集数据 + 标准答案，调用「设置 → 分析模型」里的模型，每门课 5 次
node scripts/eval-course-analysis.mjs --run .local/lms/runs/<runId> --gold .local/eval/gold --n 5
```

| 参数 | 说明 |
| --- | --- |
| `--run <目录>` | 已采集的数据，每门课一个子目录 `<Canvas 课程 ID>/{canvas,ed,handbook}.json`（同步时生成在 `.local/lms/runs/<runId>/`） |
| `--courses <文件>` | 课程列表，默认 `.local/lms/courses.json`，用来查课程代码、名称和学期 |
| `--gold <目录>` | 标准答案目录 |
| `--n <次数>` | 每门课跑几次，默认 5，最多 50 |
| `--model <ID>`、`--provider <ID>` | 临时换模型或服务商，不改设置。换服务商时不沿用设置里的密钥，只用该服务商自己的环境变量（`DEEPSEEK_API_KEY`、`ANTHROPIC_API_KEY`，或指定了同一服务商的 `COURSE_ANALYSIS_*`） |
| `--fake <目录>` | 不调用模型，改读固定输出（见下） |
| `--fixture <目录>` | 合成课程的简写：从目录里读 `course.json`、三份采集数据和 `gold.json`，默认用 `outputs/` 作为固定输出 |
| `--live` | 和 `--fixture` 一起用：改为真实调用模型 |
| `--out <目录>` | 结果目录，默认 `.local/eval/results/<开始时间>/`；不能在桌面里（解析符号链接后判断，macOS 上不区分大小写） |

缺采集数据、课程列表里没有或没有标准答案文件的课程会跳过，并在汇总里列出；标准答案文件存在但读不了、不是有效 JSON 或不符合 v1 时直接报错退出。命令行里的路径相对当前目录；默认路径（`.local/...`）和模型设置总是相对仓库根目录。多门课并行，同一门课的多次运行依次进行。按 Ctrl+C 后不再开始新的运行，当前这次调用会跑完；再按一次立即退出。

### 固定输出

`--fake` 目录里放 `1.json`、`2.json`……，内容是模型的原始回复（外层 `{ status, reason, document }`）。每门课第 k 次模型调用读 `<k>.json`，修复那次也算一次调用；没有这个文件时，用编号更小的最后一个文件。如果目录里有 `<Canvas 课程 ID>/` 子目录，这门课改读子目录。

合成课程的 `outputs/`：

| 文件 | 内容 | 结果 |
| --- | --- | --- |
| `1.json` | 作业 1 用了 Ed 的得分 24、却配 Canvas 的满分 100 | 被校验拦下，触发修复 |
| `2.json` | 正确（父项 ID 和日期写法与标准答案不同，用来测配对） | 通过，全对 |
| `3.json` | 漏了实验出勤 hurdle、测验 2 状态错、多了一个练习 | 通过校验但有错，只有评测能发现 |
| `4.json` | 和 `2.json` 相同 | 通过，全对 |

所以默认 5 次时：第 1 次读 1、2，第 2 次读 3，第 3–5 次读 4。合成课程包含跨 Canvas 和 Ed 的同一作业、带两个子项的测验组、加分项、考试附带的 hurdle 规则和单独的 hurdle。

## 结果

结果目录里：

- `<课程代码>/run-<i>.json`：每次运行的全部尝试（原始回复、校验问题、退出码、用量）、是否接受、是否调用失败、最终 document、耗时；
- `summary.json`：每门课和合计的全部指标、模式、模型、跳过的课程；
- `summary.md`：和终端输出相同的简短表格。

结果含成绩和原始回复，只放在 `.local/`（被 Git 忽略），文件权限 600。

## 局限

- 标准答案只有一份，代表你的判断；有多种合理整理方式时（例如父子拆分），和标准答案不同不一定是错。
- 名称配对只认规范化后完全相同的名称，改了措辞的考核会算漏掉 + 多出。
- `due` 只比字符串的日期部分，不换算时区：同一时刻写成 UTC 和本地时间，日期可能差一天。
- `name`、`rule`、`sources`、`materials` 不打分。
- 固定输出只验证校验和打分流程，不代表任何真实模型的水平；真实模型的结果只代表那几门课、那个时间点。
- 取消时不会中断正在进行的模型调用。
