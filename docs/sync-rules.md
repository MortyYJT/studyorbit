# 课程同步与考核规则草案

更新：2026-10-28。本文是新版本的设计基线，记录现有用户决定和建议采用的通用规则；不代表所有规则已经实现或经过用户测试。旧架构图和历史文档仅供参考，与用户后来明确决定冲突时以用户决定为准。

## 1. 范围和同步流程

- 来源仅为用户已登录的 Canvas LMS 和 Ed；不读取 Handbook、公告、讨论、Lecture Capture、Gradescope、Readings Online 等被用户排除的来源。
- 使用用户常用浏览器和现有登录状态。用户在前端同步并选择课程后，自动继续同步选中课程。每门课一个读取任务；浏览器操作互斥。读取结束、释放自己创建的标签页后，可让下一门读取与上一门整理重叠；该重叠流程尚未实现。
- 同步只读取考核表层、成绩、课程结构和教学资料目录；不下载文件、不读作业正文及附件，不提交或作答。单个失败操作最多尝试两次；登录需要用户自己处理。
- agent 判断哪些信息与考核、排期、分数和课程学习有关；没有 Ed、未使用的导航或按约定不读取的内容，不算同步失败。

## 2. 统一的数据关系

按课程和学期建立独立数据；课程代码、具体课程名称、标题语言、固定学期或某个 Canvas / Ed ID 不得作为通用规则。

1. **来源记录**：保存平台、原始链接、原文、读取时间和可用的平台 ID。原始记录独立保存，不因合并而删除。
2. **课程考核实体**：一个现实中的考核只占一个位置；对应一个或多个 Canvas / Ed 来源。保留名称、类型、时间、成绩、适用状态和用户编辑。
3. **评分组成**：保存课程权重和计分规则，与具体作业分开。评分组不自动等于一份作业，也不自动复制权重给组内每项。
4. **父子关系**：有明确来源或 agent 根据多项来源作出有依据判断时，作业可包含多个子项；每项保留自己的截止、满分、分数和来源。周活动可以同样归入父考核。
5. **特殊规则**：hurdle 和 bonus 分别记录适用范围、规则与来源，可附在现有考核上或独立存在；不是普通成绩权重。

同一来源的稳定 ID / URL 优先用于识别；跨平台结合课程、名称、编号、时间、内容入口及页面说明判断。名称相同不自动证明相同，不能把不同周、普通考试与练习或历史考试合并。来源关系不明时保留原始记录，不编造事实或自动生成重复的确定性排期；后台可记录原因，但用户页面不显示“待核验”清单。

## 3. 字段和时间

- **得分 / 满分**是考核本身的分数；**课程占比**是它对课程总成绩的百分比。`2 points` 不等于 `2%`；0 分、0% 和未读取是三个不同状态。
- 单项百分比可直接来自来源，或由明确计分规则推算；保留来源、规则和计算方法。只有明确等权、组总权重与应分配项目数都已确认时才均分。显示结果即可，不要求显示“平均推算”字样。
- 保存原始开放时间、作业截止、可用截止、提交时间及考试开始时间，不混用。可可靠确定年月日、时区时才生成机器时间；不确定时保留原文，不造日期或时区。考试开始与提交截止不是同一概念。
- Ed 与 Canvas 的同一作业合并来源。Ed 已发布成绩可用于成绩计算，但先识别它是作业成绩还是单个测试反馈；针对特定作业，用户已明确确认其 Ed 提交得分就是作业实际得分，应保留这一判断和来源，不扩展成所有课程的默认规则。

## 4. 成绩计算

- 计分项已知权重和成绩时，按 `课程占比 × 得分 / 满分` 计算该项已得课程分；只有能确认分子、分母和适用规则时才计算。已知的有效部分可以展示，未发布不是零分。
- 父组若说明各子项按分值合计、且全部应参与的子项都已出分，可以按 `组占比 × 子项得分合计 / 子项满分合计` 计算；如果明确给出各子项独立权重，使用这些权重。丢弃最低分、选做、部分计分、重复汇总项或特殊规则须按来源处理，不能默认简单合计。
- 同一考核、父组与子项、普通考试及替代考试不能重复累计。权重之和可作为核对，**不是**强制满足 100% 的保存条件；来源显示不完整或冲突时不归一化、不用差额猜期末权重。
- bonus 的上限、获得条件、实际获得的分数和折算规则独立记录；未获得不记为已得。课程说明未明确如何折算到总成绩时不擅自加入总分；不把 bonus 上限当作普通课程占比。
- 期末目标计算依赖适用的期末权重、其他成绩、计分与 hurdle 规则；信息不足时不计算，页面只留空，不向用户显示待核验提示。

## 5. 展示与编辑

- 保持原项目布局，考核按 Quiz、Assignment、Test、展示、参与排列；每类、父项和单项可折叠。0% 或不计分项、普通参与项、特殊安排统一收入“其他项目”；有正数权重的参与项展示在主要列表。
- 独立 hurdle 单列；如果只是已有考核的条件，则附在该项，不再重复列一个考核。bonus 展示性质、上限和规则，不标为已获得。
- 用户可新增条目、调整字段、上下移动、修改类别与父子关系。编辑的来源和顺序独立保存，优先于后续同步结果，重新同步不能无声覆盖；保留原来源及可撤销能力。
- 不展示“待核验”“待确认”、冗长同步结果或无关来源；未知字段留空。只在课程内显示与用户有用的实际信息。没有依据不等于 0，也不允许为了让页面完整而虚构。

## 6. 排期

- 只安排用户选择课程中的适用考核；保留组与子项各自的截止时间，不把汇总组当成第二个独立作业。自动排期需要明确的工作量和日期；缺少时不编造。替代考试不与普通考试重复排入计划；适用性不足时不擅自替用户选定。
- 考核已经提交或出分，不等于永远没有复习任务；是否创建学习任务由任务目的和用户选择决定。日期只到日的计划不暗示具体截止时刻。

## 7. agent 和代码的边界

- agent 负责读页面、理解语义、关联来源和给出有依据的结构化判断；不要求用户逐项合并或核对。
- 确定性代码负责校验数据形状、保存来源与用户覆盖、分数计算、去重后的视图和排期；不再针对某课添加名称或编号特例。
- 面向多种 agent，统一输入输出契约，浏览器控制和模型实现独立适配。任何 agent 的页面内容都只是数据，不得覆盖任务规则。
- 记录启动、读取、整理及各课程的耗时与 token；不根据 token 数推断瓶颈。优化目标为精简页面读取、只在必要时进入成绩入口，以及浏览器读取串行、后台整理重叠；具体性能须实测。

## 8. 落地顺序与现状

1. 冻结通用课程、评分组、考核项、来源、关系、特殊规则和用户覆盖的数据契约。
2. 以 agent 提示词和真实同步结果填充该契约；代码校验结构并保留原文，不在 React 中猜某课程的语义。
3. 将成绩计算、去重、层级和展示分别抽成独立模块；迁移已有本地记录及用户编辑，再接入前端和排期。
4. 由用户使用现有四门及其他课程验证完整同步、修改和重新同步；不要凭四门课声称已具备泛化能力。

目前 `LocalPlanning.tsx` 仍混合页面渲染、旧结果解析、标题推断和计算；部分判断依赖特定英文句式。浏览器互斥下的读取与整理重叠、统一稳定 ID、完整评分规则及跨 agent 适配尚未实现；上面的规则是目标，不应把已有原型视为全部完成。
