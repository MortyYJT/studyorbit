## 已完成：第 0 层原型

1. 前端点击“立即同步”后，Vite 开发服务器启动 macOS 课程脚本；脚本使用系统默认浏览器打开 Canvas 课程 API。也可在终端运行 `npm run sync:courses -- --browser edge` 指定浏览器。
2. 脚本默认等待 1 秒，执行一次全选和复制，解析 JSON，保存到 `.local/lms/courses.json`。保存成功后，确认当前标签页为本次打开的 API 页面再关闭，无法安全关闭时提示用户。使用现有浏览器登录状态，不使用扩展或 Agent。
3. `scripts/lib/course-list.mjs` 按 `course_code` 筛选：4 个字母、首位为 1–9 的 5 位数字，后接下划线或结束。原始文件保留未筛选的候选项。
4. Vite 开发服务器提供 `/api/local/sync-courses` 和 `/api/local/course-candidates`，同步成功后前端本周页面刷新并展示筛选结果，用户可勾选并保存。保存后选课栏收起，页面下方短暂显示提示；可通过“修改选课”再次打开。选择保存在该浏览器的 localStorage。

用户提供的真实数据有 9 个候选项；筛选出的课程是 COMP20003、COMP20008、MAST10007、MUSI20163。用户已认可目前的筛选规则。

- 用户已在 Mac 的 Edge 上运行取数脚本，结果文件记录了 9 条候选项、一次读取、约 1.77 秒。

- 取数脚本目前只实现 macOS，Windows 尚未适配。其他浏览器的实际行为尚未由用户验证。
- API 仅取第一页，未验证是否覆盖全部课程；其返回范围也不保证与首页卡片完全一致。
- 页面的加载等待为固定 1 秒；较慢时可手动调整 `--wait`。脚本会占用剪贴板，尝试恢复原有纯文本，但不会保留富文本或图片。
- 过滤规则基于当前样本，未验证全校课程；不符合该规则的项不会出现在选课列表中。
- 选课列表使用 Vite 开发服务器临时接口，选择保存在当前浏览器；本地课程页和周排期现读取桌面课程结果，不依赖旧后端。选择和排期保存在当前浏览器；切换浏览器或不同页面来源可能看不到。
- 前端保存选择后启动串行 Codex CLI 调度任务，每门课由调度任务请求一个 Luna subagent，前端显示进度。用户已在 2026-10-28 从前端运行四门课，四份 JSON 均已生成，程序显示 1 门完成、3 门部分完成；数据仍需用户核对，状态分类存在误判。服务重启会丢失内存中的当前进度。
- 运行期间产生的用量按课程追加到 `.local/lms/course-sync-usage.jsonl`；调度 agent 与 subagent 分开记录，无法读取到的用量为 null，不等于零。
- 用户观察到点击开始同步至第一门课标签页打开约需 10 秒，体感不佳；阶段耗时和瓶颈待核查，后续考虑优化。详见 [同步发现](sync-findings.md)。
- 用户要求每门课浏览器读取完成后关闭本任务创建的标签页，释放浏览器给下一门课，同时继续整理上一门课；浏览器操作仍保持互斥。当前调度器仍等待整个任务结束才开始下一门，重叠尚未实现。

- 本地课程页读取每门课程目录最近修改的有效分数结构 JSON；考核日期和预计工作量由用户确认后加入排期，按每日可用分钟数和截止日期分配，超期或超出一年范围的任务提示未安排。原始课程占比暂不直接采用；MAST10007 四项作业的 3.75% 根据同步结果中的明确原文计算。课程分组保留原样，不合计。替代考试仅提示用户确认，尚无完整替代版本关联。
- 该版本尚未由用户测试；当前仅开发服务器提供课程读取接口，构建后的静态页面没有配套后端。
