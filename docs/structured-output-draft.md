# 课程结构化输出草案

日期：2026-10-28。根据四门课试运行和旧项目代码整理；这是一份供用户确认和后续实现的草案，不代表现有 JSON 已符合规则。

## 用户期望

同步后直接使用可用信息排期和展示课程、考核结构。不要把“完成 / 部分完成”作为主要展示标签。确有未获取的信息或待核事项，放在对应课程里；系统内部可保留运行记录，以便失败恢复和排查。

允许合理的不完整：没有 Ed、没有测验、某些教学资料不相关，或按约定不读取的作业正文和附件，都不应算同步失败。Agent 判断信息是否与课程、排期或成绩有关；不相关的资料可跳过，但不能仅凭没有看到就断定不存在。

## 每门课的输出

为方便后续验证，建议每门课输出以下结构；字段名尚待确定，示例是表达关系，不是最终 Schema。

```json
{
  "course": {"id": "Canvas课程ID", "code": "MAST10007", "name": "Linear Algebra", "term": "2026 Semester 2"},
  "sources": [{"platform": "canvas", "url": "课程主页链接"}],
  "components": [{"id": "组ID", "name": "Written assignments", "weightPercent": 15, "sourceIds": ["来源ID"]}],
  "assessments": [{"id": "考核ID", "name": "Assignment 1", "kind": "assignment", "componentId": "组ID", "weightPercent": null, "pointsPossible": 6, "pointsEarned": null, "dueAt": null, "dueText": "页面时间原文", "submissionStatus": "unknown", "sources": [{"platform": "canvas", "url": "作业链接"}]}],
  "materials": [{"name": "Lecture notes", "url": "资料链接", "platform": "canvas"}],
  "issues": [{"subject": "考核或资料ID", "field": "dueAt", "reason": "页面未显示截止时间", "sources": ["来源链接"]}]
}
```

- **课程**：课程代码、名称、学期、各平台 ID 和入口链接。
- **考核组**：组 ID、名称、课程占比；组的占比单独存，不能复制成每个作业的个人占比。
- **考核项目**：稳定 ID、名称、类型、所属组、链接、开放/截止时间、满分、已得分、提交状态、个人课程占比（有证据才填）。一项可有多个平台来源。
- **类型**：考试、测验、作业（含论文、报告、项目）、展示、参与、不计分；缺少依据时归为类型待确认。明确为 0% 的原始分组或考核项，以及不计分项目，默认折叠；未知权重不当作 0%。组的 0% 不自动赋予其下每个项目。
- **课程资料**：相关教学目录或资料的名称、链接和来源；同步时不下载文件。
- **待核事项**：影响该课程数据或排期的缺失、冲突和无法访问的来源，记录具体对象、原因和链接。预定不读取的内容不放入待处理问题。

保留来源原文或可核对的来源链接；需要时记录原始时间文字。无证据的值为 `null`，不能用 `0` 代替。不同页面数据矛盾时保存双方并标待核，不静默覆盖。

## 与排期的关系

当前重构方向：先将 Canvas 与 Ed 的来源记录标准化，再由 agent 输出带证据的考核实体、评分组和父子关系，最后由确定性代码计算和渲染。作业、课程代码、某学期、英文标题或某门课人数不得作为通用逻辑的前提；不同来源之间有冲突时保存原文，前端不重复创建考核。用户的编辑、排序和确认结果独立保存，重新同步不能覆盖。

- 程序从有效考核项目生成任务，按用户可用时间、截止时间和可用的工作量预估排期。
- 没有截止时间或时区的项目保留在课程内，标明未知；不能编造精确时间。没有工作量预估时不要假装已排入可执行计划，可留在课程的待预估列表。
- 已提交或已评分项目根据实际状态决定是否仍有后续学习任务；不要只看“未出分”就断定没有提交。
- 排期可以使用已确认字段，不必等整门课所有资料完整；影响某一任务排期的问题只在对应课程中说明。

## 权重与 100%

如果已经确认课程中参与总成绩的**互不重叠的顶层考核组成**及其全部权重，合计通常应为 100%；作为一致性检查，而不是拒绝保存或生成排期的硬门槛。

不把父组和子组、同一考核在多个平台的记录、普通考试与其替代版本重复相加。页面展示的权重相加为 140% 或 300%，只能记录冲突并寻找依据，不能自行删掉某项、归一化，或假设一定存在父子关系。未完整读到、无权重或有来源冲突时，合计显示未知或待核，不以其他信息补齐。

**实际例子：** MAST10007 的 Canvas Assessment overview 明确写了四次书面作业等权重，合计 15%。因此每项课程占比可以计算为 15% ÷ 4 = 3.75%，记录为依据页面规则计算的结果，并保留原文和来源。本轮试运行误把组权重 15% 写到了每项，不能直接用于计算。组总权重与单项权重分开存；仅在总数和等权规则均有依据时计算，数量或规则不明确时保持未知或注明计算条件。分数满分为 6 分不代表课程占比为 6%。

## 记录关联

1. **同一来源的同一 ID**：更新同一记录，保留不同字段来源；不要按名字删除记录。
2. **Canvas 作业与测验、Canvas 与 Ed 的同一项**：优先用平台提供的关联 ID、直接链接或明确页面说明建立一个考核实体，并保留所有来源链接。
3. **名称相似但没有明确关联**：仅标为可能重复，放进课程的待核事项；不要自动合并或丢掉记录。对排期应避免把未知关系的条目当成已经确认的独立任务重复安排：先保留候选关系，在对应课程请用户确认。
4. **汇总组与具体项目**：存父子或归属关系仅在来源明确时建立；组用于分数结构展示，作业用于执行与排期，不把组另当成一个作业重复安排。

旧项目在部分情形下用规范化名称关联 Canvas quiz 和 assignment，并用名称跳过重复的 Ed lesson；这可以作为线索，但仅靠名称存在误合并或漏合并风险，尤其是同名考试版本。

## 考试去重：特殊考试与替代版本

普通考试、AEA、Special Consideration、补考或延期考试可能是**同一考核的不同版本**，但不能只凭名称断言适用对象、替代关系或用户资格。例如本次 COMP20003 有普通 mid-semester test 和 AEA 名称的版本；当前数据不足以确认用户应参加哪一个。

这里的去重主要指防止普通考试与替代考试被同时安排、重复计算。建立一个考核实体，并在来源确实说明互为替代时记录多个版本；每个版本分别保留 ID、链接、时间、可见状态和来源。若用户明确有获批替代安排，或平台明确显示个人适用版本，用适用版本替代原版安排；历史成绩保留来源，不重复算两次。若关联或适用性不明，保留为待核候选，不自动把疑似替代版本作为独立考试重复排期，也不询问或推断医疗等敏感原因。练习考试和确属独立的正式考试不因为名称相似而合并。

## 待决定及实现

具体 JSON 字段和分数计算规则尚未最终确定。现有四份试运行 JSON 结构不完全一致，也存在权重和状态误判。本地页面仅展示候选考核，由用户确认截止日期和学习时长后排期；仅针对有明确原文依据的四次等权作业展示计算权重，其他单项权重待核。替代考试目前仅按名称提示确认，尚未实现版本关联、适用性判断或自动替换。仍需调整提示词和导入规则，并由用户测试后决定最终 Schema。
