## Decisions

### Approved host and protocol boundary

Use Vite + React + react-dom + @vitejs/plugin-react and approved @types (#64/#69). Built assets live in `dist/ui`, served by the same `coursework ui` process on IPv4 `127.0.0.1`; the command opens the browser. Reuse the prototype CSS variables, monochrome palette and approved shell (#25), not its hard-coded data or fictional metrics. No calendar/router/state/test/server library is presumed. How to compose asset serving with M2's exact POST server and open a browser is O1, not an already implemented host feature.

Browser data/action traffic uses `POST /api/<command>`, JSON input and the M2 `coursework.agent/v1` envelope. Share browser-safe contract schemas/types only; never import dispatch, repositories, fake context, Node files, Q1 handlers or action drivers into the client bundle. Host synthetic registry/context executes behind real loopback HTTP. Basic M2 fake examples are fixed and do not implement filtering/paging; richer independent synthetic service fixtures are needed for meaningful UI tests. Synthetic writes stay disposable and cannot mount real action adapters.

Preserve exact Host/Origin/Sec-Fetch-Site checks, no wildcard CORS, no-store responses, 64 KiB body/envelope limits, single command execution and safe codes. Same-origin production assets avoid a Vite cross-port exception. A development proxy/origin arrangement needs O1 security verification; never weaken F to accommodate Vite. Browser bootstrap for `X-Coursework-Capability` is O2. The capability is a transport/owner gate, never a course grant or L4 consent.

Runtime-validate input and response envelopes; show loading, empty, unavailable, invalid-response and command-failure states distinctly. Echo opaque list cursors unchanged, bind paging state to filters and stop at missing continuation. Detect repeated cursors and expose bounded partial coverage rather than fetching forever. `changes` alone has exclusive numeric `since`/`nextCursor`; notifications cannot replace rereading current state. Guard stale responses after filter/course/revision changes. Preserve evidence text/hash/UTF-16 offsets exactly, show quote/locator/PDF page and limitations, and render external text as text rather than executable HTML. No automatic replay of writes/fill/submit/chat after disconnect, timeout or UNCERTAIN.

### Calendar, modules, grades and plan

The prototype interaction is already chosen (#25): month-first with week toggle, configurable teaching-week labels, module rail and nearest deadlines, task drawer, avatar status/metrics/settings with theme and Chinese/English. Preserve keyboard focus, labels, drawer dismissal/focus return, narrow/wide layouts and reduced motion. Use public handle/preset identity only; optional avatar upload handling is O9.

#31 supersedes #24's time-budget modules: all modules are delivery-type. Progress is completed / total steps in non-recurring tasks; empty denominator gives zero; recurring work is excluded. Recurring tasks have daily/weekly repeat and no due date; month cells summarize daily recurrences in one row. Do not invent completion history absent an occurrence contract (O3/O5).

Manual assessment weight and score entry is required in v1 (#28), with Canvas auto-fill later. The UI must save through a separately specified and merged M2 owner contract, reread authoritative values after save/reload and recompute projection from them; rejected/conflicting saves preserve prior authoritative state. O3 is a prerequisite for this required scope, not an option to omit manual entry. No browser-only durable store or invented grade command is permitted.

Grade projection reuses the existing pure domain behavior (#28): H1/H2A/H2B/H3/P thresholds, weighted current average, current-average assumption for ungraded non-finals, hurdle floor and secured/unreachable/unavailable reasons. Do not fork the formula or imply a guaranteed mark. Partial assessment coverage cannot yield an unqualified complete-course projection.

EDF is a pure function of explicit tasks/occurrences, planning horizon, daily available minutes and selected time/week rules. It fills capacity in earliest-deadline order; done steps require no work; overflow remains visible at risk with unscheduled minutes. Missing deadlines/estimates must stay visible rather than becoming zero work or invented deadlines. O4/O5 settle timezone, ties, splitting, recurrence, undated work and past deadlines before exact algorithm tests. Repeated identical inputs must produce identical output without reading clock/storage/network or calling an agent.

### Study and external reasoning

Read course/week notes and practice with verified citations and limitations (#70/#73). Objective practice is graded deterministically in the browser only when the answer representation supports it; M2's current `answer: string` and optional options do not establish a universal answer encoding (O6). Never grade a real assessment through this practice path. Open items go through the chat relay to Hermes; no browser model calls or fabricated local grade. Pending/unavailable feedback is not a miss. Misses update a weak-topic list and influence revision planning through selected protocol state (O3/O6); M4 owns automatic exam-window regeneration. Citation matching establishes provenance, not answer correctness.

At the start of M3, a scoped local Hermes spike must demonstrate an actually callable interface with synthetic chat/open-practice input and record safe interface/error/cancellation behavior. Do not speculate that MCP mounting supplies a chat API. If none exists, stop the relay work and ask before selecting another interface/agent; independent calendar/planning work continues. All UI relay traffic must still traverse selected registered M2 commands. Before any relay to Hermes, the trusted M2 server must redact or reject all outgoing text, including user messages, subjective/open-practice answers and selected context, for classmates' names, emails and student numbers. Browser sanitization and ingestion-time redaction alone are insufficient; if safe redaction cannot be established, reject without forwarding. Synthetic receiving-end tests must prove original personal-data sentinels never reach Hermes. Chat carries only explicit selected redacted context, never capability/confirmation tokens, raw captures or credentials; agent text cannot trigger review, consent, grants or actions. Outputs proposing record writes must pass normal M2 validators.

### Autonomy and exact owner interaction

Use #56, not obsolete no-L4 wording. L0 reads; L1 assistance; L2 drafts; L3 fills for owner review; L4 submits after owner confirmation by default. Recorded course policy and exact grants gate L2–L4, prohibited courses cap at L1, exams never above L1, unknown classification fails closed. UI labels and disabled controls explain these constraints but M2 services recheck them at execution; schema levels or cached receipts are not permission. Policy configuration remains outside UI. Auto-submit is default off and only an explicitly owner-enabled, audited per-course setting removes the confirmation step; it never bypasses other checks.

Display exact proposal answers, citations, evidence limitations and revision; use `quiz.review` only through a trusted browser-owner adapter after O7, not by calling Q1 TTY handlers from the browser. Changing source/proposal/target/page/attempt/policy/grant invalidates old review/consent. Fill is one explicit command with no submit side effect. A fill receipt is not a grade or submission. Render `partial`, `unavailable` and `uncertain` command data even under HTTP 200 and inspect failure envelopes under non-200 replies. Partial receipts with `retrySafe: false` and UNCERTAIN forbid blind repeats and require reconciliation; neither means complete fill/submission.

Before default L4 submission display the exact filled target/answers; the owner explicitly clicks submit. The trusted server issues confirmation for that bound target and the UI sends the token only to `quiz.submit`; never invent a boolean or use the session capability as consent. O7 closes the currently missing issuance/target-read seam. Honor existing token lifecycle, fresh state checks and single-use behavior; unavailable real drivers remain unavailable. M4 supplies the verified real Ed submit adapter. Never authorize a real remote action from fixture tests or a generic acceptance checklist. Claude rechecks repository privacy before pushing answering/action code (#57), even though #78 records an earlier visibility change.

## Risks / Trade-offs

- [M2 schemas mistaken for production wiring] → show explicit coverage/unavailable states; track each contract/adapter gate separately from synthetic UI evidence.
- [Feature gaps tempt side channels] → protocol extension issues first; no browser database, CLI, private file or direct Hermes/Canvas/Ed access.
- [Loopback bootstrap exposes owner capability] → settle O2 and adversarial tests before mutations; no URLs/logs/browser persistent storage/model context containing secrets.
- [Stale or ambiguous review/grade/plan] → exact revision binding, filter-aware paging, complete-input/coverage labels, no claimed success or invented time rules.
- [Hermes not callable] → first spike, stop and ask for relay choice; never introduce a model client as fallback.
- [Package creep] → approved list only, including approved @types (#69); Playwright and Vitest suffice; any additional dependency needs approval.
